# MediStock AI — Developer Documentation

> **TL;DR** — MediStock AI is a pharmacy inventory and billing system: a React SPA talking to an Express + MongoDB REST API. On top of the usual CRUD, it tracks stock per batch (with expiry and rack location), forecasts demand with an in-process TensorFlow.js LSTM, drafts purchase orders from those forecasts, and offers a bilingual (English/Tamil) voice assistant backed by Gemini.

These docs describe how the code **actually works today**, including the trade-offs and rough edges. Where the behaviour differs from what the root `README.md` promises, the docs say so.

## Who uses the system

| Persona | Logs in? | What they do |
|---------|----------|--------------|
| **Owner** (shown in UI as *Admin*) | Yes — role `owner` | Everything: financial reports, user management, forecasting parameters, approving purchase orders, audit log |
| **Staff** (shown as *Operational Staff*) | Yes — role `staff` | Day-to-day operations: billing, inventory updates, customers, Excel import, reviewing reorder drafts, chatbot |
| **Customer** | No | Exists only as a record (`Customer` collection). Receives bill notifications via email / WhatsApp when contact details are on file |

Only two roles exist in code (`userModel.js`: `enum: ['owner', 'staff']`). There is no customer-facing login.

## Glossary

| Term | Meaning in this codebase |
|------|--------------------------|
| **Batch** | A lot of one medicine with its own `batchNumber`, `expiryDate`, `quantity`, and `rackNumber`. Stored as an array inside each `Medicine` document. |
| **FEFO** | *First-Expired, First-Out* — consume the batch closest to expiry first to reduce expiry waste. |
| **Rack number** | Physical shelf location of a batch in the shop. |
| **Reorder level** | Per-medicine threshold (`reorderLevel`, default 50). At or below it, stock is "low". |
| **Stock status** | `low` (≤ reorderLevel/2), `medium` (≤ reorderLevel), `high` (above). Computed by `getStockStatus()`. |
| **AI Draft** | A `PurchaseOrder` with `order_status: 'AI_Draft'`, generated by forecasting and awaiting human review. |
| **Forecast horizon** | How many **weeks** ahead the forecast predicts (1–12, default 4). |
| **Lead time** | Days between placing an order and receiving it (default 7). Used to size reorder quantities. |
| **Safety stock %** | Extra buffer on top of predicted demand (default 20%). |
| **Seasonal multiplier** | Per-month factor applied to predicted demand (e.g. `oct: 1.4`). |
| **Audit log** | Append-only record of mutating actions (`AuditLog` collection), viewable by the owner. |
